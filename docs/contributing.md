# Contributing

## Before opening a change

1. Keep changes focused and consistent with the existing architecture.
2. Run `npm run lint`.
3. Run `npm run build`.
4. Update documentation when routes, configuration, API behavior, or user workflows change.
5. Do not commit `.env.local`, credentials, API keys, private datasets, or generated output.

## Documentation expectations

User-facing behavior belongs in `docs/user-guide.md`. Setup instructions belong in `docs/getting-started.md`. Technical design and data flow belong in `docs/architecture.md` and `docs/developer-guide.md`.
